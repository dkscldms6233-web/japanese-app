# 씨앗 유료 구매 연결 안내 (구글 플레이 결제)

코드는 `billing.js`와 `path.js`(상점)에 들어 있고, 지금은 **꺼져 있어요**. 아래 순서대로 준비가 끝나면 켭니다.

## 켜지는 조건 (모두 맞아야 상점에 "씨앗 사기"가 보여요)
1. 플레이스토어에 올라간 앱(TWA)에서 열었을 때만 (웹 브라우저·설치 안 한 PWA에서는 안 보여요)
2. `billing.js`의 `CFG.on=true`
3. `billing.js`의 `CFG.verifyUrl`에 서버 검증 주소가 들어 있을 것
4. 로그인한 계정일 것 (게스트는 안내 문구만 보여요)

## 준비 순서
1. 구글 플레이 개발자 계정 만들기 (등록비 25달러, 본인 인증)
2. 앱(AAB) 올리기 — `store/apk/surasura-nihongo.aab`. 플레이 앱 서명을 쓰면 서명 지문(SHA-256)을 `.well-known/assetlinks.json`에 추가해야 해요
3. 플레이 콘솔 → 수익 창출 → 인앱 상품에 "관리형 상품" 만들기: `seeds_100`, `seeds_300`, `seeds_700` (ID는 `billing.js`의 `packs`와 같아야 해요. 가격은 콘솔에서 정하면 앱에 자동으로 표시돼요)
4. 서버 검증 만들기 (아래)
5. 앱 업데이트 올리고 테스트 계정(라이선스 테스터)으로 결제 시험 → `CFG.on=true`, `verifyUrl` 채우고 배포

## 서버 검증 (Firebase Functions, Blaze 요금제 필요)
앱이 보낸 `{sku, token}`과 로그인 토큰을 받아서:
1. 로그인 토큰으로 사용자 확인 (이메일 인증된 계정만)
2. Google Play Developer API `purchases.products.get`으로 `token`이 진짜이고 결제 완료 상태인지 확인
3. 같은 `token`이 이미 처리된 적 없는지 Firestore에서 확인 (중복 지급 방지)
4. `purchases.products.acknowledge`로 승인 (3일 안에 안 하면 자동 환불돼요)
5. `{ok:true, seeds:<sku에 해당하는 개수>}` 응답 (씨앗 개수는 서버가 정해요. 앱이 보낸 숫자를 믿지 않아요)

## 아직 안 된 것 / 알아둘 점
- 실제 결제는 한 번도 시험하지 못했어요 (플레이 계정이 없어서). 모의 결제로 "구매 → 서버 확인 → 씨앗 지급" 흐름만 확인했어요.
- 씨앗은 아직 기기에 저장돼서(`jp-char`), 서버 검증이 있어도 기기 데이터를 지우면 구매한 씨앗도 사라져요. 정식 판매 전에 씨앗을 계정(Firestore)에 저장하도록 바꾸는 작업이 필요해요.
- 한국에서 판매하려면 통신판매업 신고, 세금 신고, 환불·이용약관 안내가 필요할 수 있어요. 구청·세무서에 확인하세요.
- 앱 안 디지털 상품은 구글 정책상 구글 결제만 써야 해요 (토스 등 외부 결제로 돌리면 정책 위반).
